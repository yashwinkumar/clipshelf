# Clipshelf

A small clipboard history app for macOS, built with Tauri and Rust.

## Quick summary

Clipshelf captures plain text into local history with search, copy-back and keyboard controls. The green bottom panel supports capture pause and resume. Milestones M0 to M6 are implemented; M7 adds launch and error handling. Local macOS app bundles are available from source. The source is MIT licensed. Signing and notarization remain pending.

## What works today

- Menu bar item with Show panel, Pause or resume capture, and Quit.
- Polls the system clipboard every 250 ms and waits 300 ms after a change settles.
- Reads copied plain text, skips copies with one of six marker types without reading them (see [PRIVACY.md](PRIVACY.md)), and skips empty text, text over 100 KB, and copies with no plain text.
- Stores accepted text in a local SQLite history: capture time and best effort source app. Newest 500 entries are kept. An identical copy of the newest entry is not stored twice.
- A history view lists entries newest first. Search is a literal substring match, case insensitive for ASCII.
- The panel sits along the bottom of the display under the pointer, above the Dock. Open it from the menu bar item (Show panel). Its close button hides it; capture keeps running.
- Each history entry has a Copy control (icon, shown on hover, focus or selection). It writes the text to the clipboard as plain text; you then paste with Cmd+V. Clipshelf never simulates keystrokes and needs no Accessibility permission.
- Its own write is recognised and not captured again. A copy made by another app is still captured.
- Never writes clipboard content to logs or error messages.

## Requirements

- macOS 14 or newer. Developed and tested on macOS 26.
- Apple silicon Mac. Intel support has not been verified.
- Rust 1.90 or newer (`rustup`).
- Node.js 20 or newer and npm.
- Xcode Command Line Tools (`xcode-select --install`).

Other operating systems are not supported. The code builds elsewhere only so unit tests can run.

## Build and run from source

```sh
git clone https://github.com/yashwinkumar/clipshelf.git
cd clipshelf
```

```
npm install
npm run dev        # development window, menu bar item and capture loop
npm test           # unit tests (Rust)
```

Build a local app bundle from this directory:

```sh
npm run bundle:debug
# Output: src-tauri/target/debug/bundle/macos/Clipshelf.app
npm run bundle
# Output: src-tauri/target/release/bundle/macos/Clipshelf.app
```

The debug bundle has been built locally. The release command is provided but has not yet been exercised. Build for your current Mac architecture; a universal distribution is not configured. Open the app bundle in Finder, or copy it to your Applications folder for local use. Bundles are unsigned and not notarized; there is no downloadable installer or automatic updater yet. Do not disable macOS security protections to open a downloaded copy.

## Layout reference

The look is modelled on a commercial clipboard manager's panel, observed from the owner's own screenshots. Clipshelf uses its own branding, colours and code. See `ARCHITECTURE.md` for the layout rules and `src/css/tokens.css` for the values.

## Data locations

- Development (`npm run dev`): `~/Library/Application Support/dev.promptlyashwin.clipshelf/dev/history.sqlite3`
- Release builds: `~/Library/Application Support/dev.promptlyashwin.clipshelf/history.sqlite3`

Reset development history by quitting the app and deleting the `dev/` folder. See [PRIVACY.md](PRIVACY.md).

## Try it with synthetic data

The helper script writes made up text to the clipboard. It replaces whatever you have copied.

```
osascript -l JavaScript scripts/write-test-item.js plain
osascript -l JavaScript scripts/write-test-item.js concealed
```

Kinds: `plain`, `transient`, `autogenerated`, `concealed`, `petermaurer`, `typeit4me`, `generated`.
Watch the terminal that runs `npm run dev`. Lines start with `[capture]` and carry no clipboard text.

## Keyboard controls

- Control+Option+Space toggles the panel globally.
- Command+F focuses and selects the search query.
- Down moves from search to the selected card. Left and Right move between cards while a card has focus. Up and Down also navigate cards.
- Home and End select the first and last visible result.
- Enter copies the selected result. Command+C copies while a card has focus. In the search field, Command+C retains normal text-copy behaviour.
- Escape hides the panel. Paste into the destination manually with Command+V.

The global shortcut is configurable through `settings.json` beside the history database. Set `panel_shortcut` to a Tauri shortcut string, such as `Control+Alt+Space`, and restart Clipshelf. If the configured shortcut cannot register, Clipshelf tries the default. If both are unavailable, use the tray menu. Configuration is separate for development and release, like the database.

## Capture pause and troubleshooting

Use the pause icon beside the close control, or the tray's Pause or resume capture action. History search and copy-back remain available while capture is paused. Copies made while paused are not imported on resume. Pause is session-only and resets when Clipshelf restarts.

If a text copy cannot be read, the panel reports it without recording the content. Review macOS clipboard access for Clipshelf and copy again. A read failure does not establish whether the cause was a permission, an unavailable item or another clipboard change. Storage failures produce a separate message. Disk-full and permission-denied cases have not been induced in the live app.

Only one instance runs per app identifier. Opening another instance reveals the existing panel. Opening the running app from Finder also reveals it.

## Clear history

Use the trash icon in the toolbar. Confirm Clear all history to remove every saved item, including items outside the current search. Cancel or Escape closes the confirmation without deleting. Your current clipboard stays unchanged, and capture keeps its existing paused or active state. New copies can populate history again. Clearing has no undo.
