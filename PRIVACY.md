# Privacy and data

Clipshelf is a clipboard manager, so it handles sensitive data. This page states what it does today.

## What is read

- The clipboard change count, the list of type names on the clipboard, and the frontmost app name and bundle identifier.
- Plain text, but only after the type check passes.

## What is skipped without reading

A copy is skipped, and its content is not read, when it carries any of these types:

- `org.nspasteboard.TransientType`
- `org.nspasteboard.AutoGeneratedType`
- `org.nspasteboard.ConcealedType`
- `de.petermaurer.TransientPasteboardType`
- `com.typeit4me.clipping`
- `Pasteboard generated type`

Password managers commonly set the concealed marker. Skipping on these types is a decision of this project, not a guarantee that secrets are never captured. Apps that set no marker are not recognised.

Also skipped: empty text, text over 100 KB, and copies with no plain text.

## What is kept

- Accepted text, its capture time (milliseconds since 1970), and the best effort source app bundle identifier and name, in a local SQLite file.
- The newest 500 entries. Older entries are deleted automatically on each new capture.
- An identical copy of the newest entry is not stored again.
- Excluded copies and their text are never stored. Nothing is kept for them except counts and the marker type name in the event.

## What is logged

- Logs and interface events contain counts, outcomes, reasons, storage results and app labels. They never contain clipboard text or search text.
- Storage error messages are fixed text and carry no content.

## Copy back

Copy writes the chosen text to the system clipboard as plain text. After that, any app, and any other clipboard manager you run, can read it like any copied text. Clipshelf does not mark the write as concealed or transient, so a clipboard manager that records everything will record it. Clipshelf does not press keys or paste for you.

## Icons

The panel shows each source app's icon. Icons are read from the apps installed on this Mac, by bundle identifier, and kept only in memory for the session. Nothing about them is sent anywhere.

## What leaves the Mac

Nothing. The app has no network code. Clipboard text stays in the local database.

## Data locations

- Development (`npm run dev`): `~/Library/Application Support/dev.promptlyashwin.clipshelf/dev/history.sqlite3`
- Release builds: `~/Library/Application Support/dev.promptlyashwin.clipshelf/history.sqlite3`

Development and release data never share a file. The file is created with owner only permissions (0600). SQLite may also create temporary `-journal` files beside it while writing.

To clear history, quit the app and delete the database file (and the `dev/` folder for development data). Deleting the file does not remove copies the system or other apps made.

Note: the release location is defined in code and is not yet tested with a packaged release build.

## macOS permission behaviour

macOS 15.4 and later can ask before an app reads the clipboard programmatically, controlled in System Settings. On the test machine (macOS 26.5) reads succeeded and the raw access behaviour value reported was 2, with no prompt seen in the logs. This may differ on other Macs or settings.

## Pausing capture

While paused, the poller reads only the clipboard change counter to discard intervening changes. It does not read types, text or source applications, and stores no new entries. Resuming rebases the counter so the currently copied item is not imported retroactively. Existing history remains searchable and copyable. Pause does not erase history and does not persist across restarts.

## Clearing saved history

The toolbar's Clear all history action deletes all rows in the active development or release database after confirmation. It also drops the latest in-memory captured text and invalidates queued capture callbacks. It does not modify the native clipboard or the other database. New copies are captured normally unless capture is paused. This is logical deletion, not a guarantee of forensic erasure from SQLite pages, journals, operating-system memory or backups.
